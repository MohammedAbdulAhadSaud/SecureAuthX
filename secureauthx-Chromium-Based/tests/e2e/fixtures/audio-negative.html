Audio Fingerprint Detector — NEGATIVE / Control Test

Local diagnostic page only. Not part of SecureAuthX. This page uses ordinary Web Audio: a regular (online) AudioContext playing a brief, quiet tone — the kind any game or notification sound uses — plus a manually-built AudioBuffer that is read with getChannelData(), deliberately WITHOUT ever going through OfflineAudioContext.startRendering(). This exercises the same hooked method (getChannelData) as the positive test, but on a buffer the detector's WeakSet was never told about — proving it distinguishes "reading audio data" in general from "reading data from an offline-rendered buffer" specifically. No OfflineAudioContext is created anywhere on this page. Nothing is sent anywhere.
How to use this page: open the SecureAuthX popup and check the Fingerprinting section, click "Run Ordinary Audio" below (a brief, quiet tone will play — Chrome requires a user click before audio can start), then re-check the popup. Expected: Fingerprinting 0, "No fingerprinting techniques detected", no audioFingerprint entry.
